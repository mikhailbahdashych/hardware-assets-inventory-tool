# Phase 2: Auth Slice (Password) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline execution chosen by the user — the main model implements directly). Steps use checkbox syntax for tracking.

**Goal:** Complete password authentication vertical slice: first-run setup, login with httpOnly-cookie JWT + rotating opaque refresh tokens (reuse detection, multi-tab grace), me/logout/change-password, global guard chain (JwtAuth → Roles → MustChangePassword), login throttling, auth audit events — plus the Angular auth core (store, interceptor, guards), setup/login/change-password pages, and the app shell with role-filtered nav.

**Architecture:** Backend: `auth` module (controller/service/token.service/password.service, jwt-access passport strategy with cookie extractor), minimal `audit` module (AuditService.log only — interceptor comes Phase 8), guards+decorators in `common/`. Refresh tokens are opaque 256-bit values stored as sha256; rotation links rows via `replacedById`; reuse after a 30s grace revokes every active token of the user. Frontend: signals `AuthStore`, functional guards, single-flight 401→refresh→retry interceptor, standalone pages, `Shell` layout (sidenav + toolbar + role-filtered nav).

**Tech Stack additions:** argon2, @nestjs/jwt, @nestjs/passport + passport + passport-jwt, cookie-parser, @nestjs/throttler, class-validator + class-transformer (+ @types/cookie-parser, @types/passport-jwt).

## Global Constraints

- Branch `feat/phase-2-auth`; Node PATH export as always; never push; commit trailer as always; dev DB container running (`.env` PORT 5433 on this machine).
- **API contracts (Phase 3+ and the FE depend on these exactly):**
  - `GET /api/v1/auth/setup-status` (public) → `{ setupRequired: boolean }` (true while user count == 0)
  - `POST /api/v1/auth/setup` (public) `{ email, password, displayName }` → 201 `{ user }`; 403 once any user exists; transactional; creates ADMIN with mustChangePassword=false
  - `POST /api/v1/auth/login` (public, throttled 5/min/IP) `{ email, password }` → 200 `{ user }` + cookies; 401 wrong creds (audit `login_failed`); 403 inactive user
  - `POST /api/v1/auth/refresh` (public route, needs valid `sit_refresh` cookie) → 200 `{ user }` + rotated cookies; reuse-after-grace ⇒ revoke all user tokens + 401
  - `POST /api/v1/auth/logout` (authed or bare refresh cookie) → 204, revokes presented refresh token, clears both cookies
  - `GET /api/v1/auth/me` (authed) → `{ user }`
  - `POST /api/v1/auth/change-password` (authed, allowed under mustChangePassword) `{ currentPassword, newPassword }` → 204, clears mustChangePassword, revokes all other refresh tokens, audit `password_change`
  - `user` shape everywhere: `{ id, email, displayName, role, isActive, mustChangePassword, mfaEnabled, mfaEnforced }` — never passwordHash/mfaSecret (enforced by @Exclude + ClassSerializerInterceptor).
- **Cookies:** `sit_access` — JWT (payload `{ sub, email, role, mcp }`, `mcp`=mustChangePassword), TTL from `ACCESS_TOKEN_TTL` (15m), httpOnly, SameSite=Lax, path=/, secure from config. `sit_refresh` — 64-hex opaque (32 random bytes), TTL from `REFRESH_TOKEN_TTL` (7d), httpOnly, SameSite=Strict, **path=/api/v1/auth**, secure from config. Names are constants in `auth/auth.constants.ts`.
- **Guard chain (global, this order):** `JwtAuthGuard` (honors `@Public()`) → `RolesGuard` (`@Roles(...roles)`, no metadata = any authed) → `MustChangePasswordGuard` (when JWT `mcp` true, only allow `/auth/change-password`, `/auth/me`, `/auth/logout`).
- **Rotation semantics:** presenting an unknown/expired refresh → 401. Presenting a rotated-away token: within 30s of its `revokedAt` → benign multi-tab race ⇒ mint a fresh pair (no family revocation); after 30s ⇒ theft ⇒ set `revokedAt=now` on ALL the user's active refresh tokens, audit metadata `{ reuse: true }`, 401.
- **Password policy:** MinLength 12, MaxLength 128 (setup, change-password; reused by Phase 4 user creation).
- **Audit:** every flow logs via `AuditService.log()` (await, simple insert): `setup`, `login`, `login_failed` (actorEmail only, actorId null), `logout`, `password_change`. Metadata always includes `ip` and `userAgent` when available.
- FE dev proxy makes cookies same-origin — no withCredentials gymnastics anywhere.
- TDD: unit tests first for PasswordService + TokenService rotation logic; e2e per endpoint group before wiring the next.

## Risks
- Cookie assertions in supertest: parse Set-Cookie manually (supertest agent keeps a jar for happy paths; explicit header asserts for attributes).
- Throttler in e2e can poison later tests (429s) — throttle spec runs last in its file or uses a distinct IP header? ThrottlerGuard keys by IP; e2e all same IP. Mitigate: put throttle test in its own describe at file end; other tests stay under 5 logins/min per file thanks to serial execution and helper reuse of sessions. If flaky, override ThrottlerStorage in TestingModule for the throttle spec only.
- ClassSerializerInterceptor needs entities returned from controllers to be class instances (repository returns entities ✓; plain objects pass through — ensure `me`/login return the entity instance).
- passport-jwt cookie extraction: custom extractor `(req) => req.cookies?.[ACCESS_COOKIE] ?? null`.
- Angular zoneless: APP_INITIALIZER async + signals fine; ensure `provideHttpClient(withInterceptors([...]))` order (auth interceptor last so it sees final 401s).
