# Phase 3: MFA (TOTP) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline execution — the main model implements directly). Steps use checkbox syntax.

**Goal:** Authenticator-app TOTP as a second login factor with single-use recovery codes, admin-driven per-user enforcement (plus `MFA_ENFORCE_ALL`), AES-256-GCM-encrypted secrets, an enrollment lockdown guard mirroring the password-change pattern, a `reset-mfa` CLI escape hatch, and the full Angular flow (login code step + QR enrollment page + recovery-code reveal).

**Architecture:** `CryptoService` (AES-256-GCM, key = `APP_ENCRYPTION_KEY` hex) + `TotpService` (otplib) inside the auth module. Login branches: password OK + `mfaEnabled` → `{ mfaRequired: true, ticket }` (5-min JWT, `purpose: 'mfa'`, signed with `JWT_REFRESH_SECRET` — deliberately repurposed as the ticket secret; a ticket can never pass the access-cookie extractor). `POST /auth/login/mfa` verifies ticket + TOTP (±1 step) or an unused recovery code, then issues the normal cookie session. Enrollment lockdown via a new `mfp` JWT claim (`mfaEnforced && !mfaEnabled`, or `MFA_ENFORCE_ALL`) enforced by `MfaEnrollmentGuard` + `@AllowedDuringMfaEnrollment` (copy of the reviewed password-change pattern).

## Global Constraints

- Branch `feat/phase-3-mfa`; Node PATH export; no push; commit trailer; dev DB running.
- **API contracts (FE + Phase 4 depend on these exactly):**
  - `POST /auth/login` → `200 { user }` + cookies **or** `200 { mfaRequired: true, ticket }` (no cookies). Shared type: `LoginResponse = SessionUser | { mfaRequired: true; ticket: string }` (discriminate on `'mfaRequired' in response`).
  - `POST /auth/login/mfa` (public, throttled 5/min) `{ ticket, code }` → `200 { user }` + cookies. 401 bad/expired ticket or wrong code (audit `login_mfa_failed`); recovery codes are consumed on use (audit metadata `{ recoveryCode: true }`).
  - `POST /auth/mfa/setup` (authed) → `200 { otpauthUri }`; regenerates while unverified; 409 if already enabled.
  - `POST /auth/mfa/verify` (authed) `{ code }` → `200 { recoveryCodes: string[] }` (shown ONCE) + fresh session cookies (clears `mfp`); sets `mfaEnabled` + `mfaVerifiedAt`; audit `mfa_setup`.
  - `DELETE /auth/mfa` (authed) `{ code }` → 204; 403 when `mfaEnforced` or `MFA_ENFORCE_ALL`; audit `mfa_disabled`; clears secret + codes + flag.
  - Recovery codes: 10 codes, format `xxxxx-xxxxx` (crockford-ish base32, 50 bits), sha256-hashed at rest, single-use (`usedAt`).
- **JWT claims:** access payload gains `mfp: boolean`. `mfp` gates everything except routes marked `@AllowedDuringMfaEnrollment` (me, logout, mfa/setup, mfa/verify). Guard order: Throttler → JwtAuth → Roles → MustChangePassword → MfaEnrollment.
- **Ticket JWT:** `{ sub, purpose: 'mfa' }`, 5m TTL, secret `jwt.refreshSecret`; verification rejects wrong purpose. Update `.env.example` comment: JWT_REFRESH_SECRET signs MFA login tickets.
- Secrets at rest: `mfaSecret` column stores `iv.ciphertext.tag` (base64 triple) via CryptoService; never logged/serialized (@Exclude already).
- CLI: `apps/api/src/cli/cli.ts` — `reset-mfa <email>` (clears secret/flag/codes + audit `mfa_reset`, actor null, metadata `{ cli: true }`); uses the data-source directly; script `npm run cli -- reset-mfa x@y.z`.
- TDD: Crypto/Totp/recovery-code services unit-first; each endpoint group e2e before FE.

## Risks
- otplib API shape (v12 vs v13 authenticator import paths) — verify at install, adapt.
- Time-based test flakiness — pin with jest fake timers or accept window-1 tolerance and compute codes at runtime.
- Ticket replay: ticket is single-purpose but multi-use within 5m by design (retry wrong code); acceptable — code attempts are throttled; note in ARCHITECTURE.md.
- QR data-URI rendering under CSP later (Phase 10 nginx) — data: URIs for img-src need allowing; ledger note.
- `mfp` staleness (admin enforces mid-session): user's claim updates at next refresh (≤15m) — same accepted tradeoff as `mcp`/role; document.
